# 估值锚定

改编自 Anthropic `dcf-model` + `comps-analysis`，整合定数录 BS 检测器和灵光估值定律。A 股适配。

## 输入

| 来源 | 内容 | 格式 |
|------|------|------|
| 用户消息 | 定数录估值路由、BS 检测器（EV/NOPAT/ROIC/WACC/隐含g/市场溢价）、三情景推演、交易标注、预期差判定 | Markdown/JSON |
| financial 输出 | 修正后的毛利率（如有）、新旧业务毛利率差异 | 结构化数据 |
| data-verify 输出 | 当前 PE/PB/市值、PE 分位 | 结构化数据 |
| 灵光库 | 起涨估值定律、毛利率天花板定律 | JSON |

## 输出

| 去向 | 内容 | 格式 |
|------|------|------|
| → decision | 起涨估值检查结果、反向 DCF 隐含 g 及判定、可比公司估值表、修正后三情景（如定数录有误）、不对称比、预期差方向及置信度 | 结构化表格 + 数值 |

## 核心原则

**估值不是单一数字——是「市场在定价什么」vs「我认为会发生什么」的差距分析。**

### 2. 起涨估值检查（灵光：起涨估值定律）

- PE > 50x → 标注「估值警戒」
- PE 分位：高估/低估区间？
- Forward PE：盈利增速能否消化？

### 3. 模型路由审计 ⭐ 核心

**不重算 DCF。检验定数录的模型选择是否合理。**

定数录输出包含：`主模型: X | 校验: Y | 理由: ...`

审计步骤：

**Step A — 模型适用性快速对照**

| 定数录选的模型 | 适用场景 | 不适用场景 |
|--------------|---------|-----------|
| A (ROIC-RR DCF) | ROIC>8%, 盈利稳定, ROIC改善可期 | ROIC<8%, 亏损, 金融股 |
| B (PS+TAM) | 收入爆发增长, 微利/亏损, 市场为TAM定价 | 成熟盈利公司 |
| C (盈利拐点) | 明确盈利拐点即将到来 | 已稳定盈利的公司 |
| G (PEG) | 增速>30%, PE可解释 | 增速<15%, 周期股 |
| I (盈利正常化) | 周期股, 利润剧烈波动 | 稳定增长公司 |

**Step B — 判断逻辑**

对照定数录的「路由理由」，逐条检验：

- [ ] 路由理由引用的 ROIC/GM/增速数据是否与 data-verify 一致？
- [ ] 如果理由引用「新业务高毛利」→ 这个毛利数据是否已经过异常检测验证？
- [ ] 模型选择是否匹配公司当前状态？（亏损→不能用 A，周期→不能用 G）

**Step C — 定数录常见路由错误**

| 错误模式 | 表现 | 案例 |
|---------|------|------|
| 高估新业务毛利导致模型选择偏向乐观 | B 模型用 96.5% GM 假设（实际是废料） | 本川智能 |
| 亏损公司被路由到 A 模型 | ROIC 数据来自非经常性盈利 | — |
| 周期股被路由到 G 模型 | 用景气高点增速外推 | — |

**Step D — 结论**

- 「定数录模型路由合理，数据基础已验证」→ 直接使用其估值输出
- 「模型路由可接受，但某假设需要修正」→ 标注修正项
- 「模型路由错误」→ 标注原因，建议替代模型

### 4. BS 检测器审计

**不重算反向 DCF。检验定数录的 BS 检测器输入是否合理。**

- [ ] NOPAT 取值是否合理？（与 tushare 利润表对照）
- [ ] WACC 取值是否合理？（Rf/Beta/ERP 参照值是否在合理范围）
- [ ] ROIC 计算是否正确？
- [ ] **如果 NOPAT ≤ 0 → BS 检测器不适用，告知用户**
- [ ] 隐含 g 和 g/WACC 的判定是否与常识一致？

### 5. 三情景推演 + 定数录比对 ⭐

**核心原则：闭卷推导 → 开卷对比。上游参数是用来质疑的，不是用来微调的。**

#### Step A — 闭卷独立推导（先不看定数录的三情景数字）

基于 data-verify + financial + industry + WebSearch 的独立发现，从零构建三情景。**顺序不能乱：先自己算完，再打开定数录对照。**

**参数 ① — 营收 CAGR（从产品增速自下而上推导）**：

```
Base CAGR = Σ(产品i收入占比 × 产品i预期增速)

来源要求:
- 新业务增速 → 从 financial segment 的 YoY 增速出发，叠加 industry 的 TAM 增速 + WebSearch 的行业 CAGR
- 传统业务增速 → GDP 增速 + 行业自然增长
- 必须展示推导过程，不能只给一个数字
```

**参数 ② — 目标 PS/PE（从可比公司 + 案例库搜索）**：

```
来源要求（按优先级）:
1. 案例库: case-match 中找到的可比案例的 PS 扩张/压缩幅度 → 折扣率换算
2. 可比公司: 搜索同赛道 A 股公司当前 PS，取合理区间
3. 行业基准: WebSearch "{行业} PS 估值 平均水平"

禁止: 直接使用定数录的 PS 假设而不标注「引用+接受理由」
```

**参数 ③ — 概率（从催化剂逐个推导）**：

```
来源要求:
- 每个 Critical Catalyst 单独评估通过概率
- Bull 概率 ≈ Π(各催化剂通过概率) 的加权
- Bear 概率 ≈ 关键催化剂失败概率 × 连锁反应系数
- 必须展示推导过程
```

**参数 ④ — Bear 必须独立构建**：

Bear 不是「Base 的收入砍半、PS 砍半」。必须：
- 具体的证伪事件链（什么催化剂失败 → 引发什么连锁反应）
- 证伪后的估值锚切换逻辑（PS→PE？PE 压缩到多少？为什么？）

#### Step B — 开卷对比（现在可以看定数录了）

逐个参数对比你的和定数录的：

| 参数 | 你的值 | 你的推导依据 | 定数录值 | 定数录推导依据 | 差异原因 |
|------|:---:|------|:---:|------|------|
| Base CAGR | | | | | |
| Base PS | | | | | |
| Bull PS | | | | | |
| Bear 逻辑 | | | | | |
| Bull概率 | | | | | |

#### Step C — 综合裁定

逐项判断谁的参数更可信：

```
差异 < 10pct → 参数基本一致，采用定数录（数据源更全）
差异 10-30pct → 审视谁的逻辑链更完整，择优采用或折中
差异 > 30pct → 你的独立推导有充分依据 → 采用你的，标注定数录的问题
```

**结论格式**：
```
定数录三情景参数质量: [可靠 / 部分需修正 / 存在错误]
采用方案: [完全采用 / 折中 / 独立参数]
关键差异及原因: [逐项]
```

### 6. 不对称比 + 预期差

用你自己的三情景计算不对称比，与定数录对比：

```
你的不对称比: X.X | 定数录: Y.Y | 差异原因: ...
```

预期差用定数录的 BS 检测器输出（已在 Step 4 审计过输入），加上你自己的判断。

### 7. 估值综合结论

| 项目 | 结论 |
|------|------|
| 定数录模型路由 | 合理 / 需修正 / 错误 |
| 三情景 | 你 vs 定数录的主要差异及原因 |
| 建议采用 | 你的 / 定数录的 / 折中 |
| 不对称比 | 你 vs 定数录 |
| 估值安全边际 | 充足 / 一般 / 不足 |
