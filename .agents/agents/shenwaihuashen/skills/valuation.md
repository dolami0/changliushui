# 估值锚定

改编自 Anthropic `dcf-model` + `comps-analysis`，整合定数录 BS 检测器和灵光估值定律。A 股适配。

## 输入

| 来源 | 内容 | 格式 |
|------|------|------|
| 用户消息 | 定数录估值路由、BS 检测器（EV/NOPAT/ROIC/WACC/隐含g/市场溢价）、三情景推演、交易标注、预期差判定 | Markdown/JSON |
| financial 输出 | 修正后的毛利率（如有）、新旧业务毛利率差异 | 结构化数据 |
| data-verify 输出 | 当前 PE/PB/市值、PE 分位 | 结构化数据 |
| 灵光库 | 起涨估值定律、毛利率天花板定律 | JSON |

## 输出

| 去向 | 内容 | 格式 |
|------|------|------|
| → decision | 起涨估值检查结果、反向 DCF 隐含 g 及判定、可比公司估值表、修正后三情景（如定数录有误）、不对称比、预期差方向及置信度 | 结构化表格 + 数值 |

## 核心原则

**估值不是单一数字——是「市场在定价什么」vs「我认为会发生什么」的差距分析。**

### 2. 起涨估值检查（灵光：起涨估值定律）

- PE > 50x → 标注「估值警戒」
- PE 分位：高估/低估区间？
- Forward PE：盈利增速能否消化？

### 3. 模型路由审计 ⭐ 核心

**不重算 DCF。检验定数录的模型选择是否合理。**

定数录输出包含：`主模型: X | 校验: Y | 理由: ...`

审计步骤：

**Step A — 模型适用性快速对照**

| 定数录选的模型 | 适用场景 | 不适用场景 |
|--------------|---------|-----------|
| A (ROIC-RR DCF) | ROIC>8%, 盈利稳定, ROIC改善可期 | ROIC<8%, 亏损, 金融股 |
| B (PS+TAM) | 收入爆发增长, 微利/亏损, 市场为TAM定价 | 成熟盈利公司 |
| C (盈利拐点) | 明确盈利拐点即将到来 | 已稳定盈利的公司 |
| G (PEG) | 增速>30%, PE可解释 | 增速<15%, 周期股 |
| I (盈利正常化) | 周期股, 利润剧烈波动 | 稳定增长公司 |

**Step B — 判断逻辑**

对照定数录的「路由理由」，逐条检验：

- [ ] 路由理由引用的 ROIC/GM/增速数据是否与 data-verify 一致？
- [ ] 如果理由引用「新业务高毛利」→ 这个毛利数据是否已经过异常检测验证？
- [ ] 模型选择是否匹配公司当前状态？（亏损→不能用 A，周期→不能用 G）

**Step C — 定数录常见路由错误**

| 错误模式 | 表现 | 案例 |
|---------|------|------|
| 高估新业务毛利导致模型选择偏向乐观 | B 模型用 96.5% GM 假设（实际是废料） | 本川智能 |
| 亏损公司被路由到 A 模型 | ROIC 数据来自非经常性盈利 | — |
| 周期股被路由到 G 模型 | 用景气高点增速外推 | — |

**Step D — 结论**

- 「定数录模型路由合理，数据基础已验证」→ 直接使用其估值输出
- 「模型路由可接受，但某假设需要修正」→ 标注修正项
- 「模型路由错误」→ 标注原因，建议替代模型

### 4. BS 检测器审计

**不重算反向 DCF。检验定数录的 BS 检测器输入是否合理。**

- [ ] NOPAT 取值是否合理？（与 tushare 利润表对照）
- [ ] WACC 取值是否合理？（Rf/Beta/ERP 参照值是否在合理范围）
- [ ] ROIC 计算是否正确？
- [ ] **如果 NOPAT ≤ 0 → BS 检测器不适用，告知用户**
- [ ] 隐含 g 和 g/WACC 的判定是否与常识一致？

### 5. 三情景推演 + 定数录比对 ⭐

**先独立推演，再与定数录对比。差异即洞察。**

#### Step A — 独立推演

基于 data-verify + financial + industry 的结论，独立构建三情景：

| 情景 | 概率 | 核心假设 | 营收 CAGR | 目标 PS | 目标市值 | 涨跌幅 |
|------|------|---------|:---:|:---:|------|------|
| Bull | | | | | | |
| Base | | | | | | |
| Bear | | | | | | |

**每个参数必须标注来源（强制）**：

```
Bull 营收 CAGR: 60% — 来源: [独立/引用]
  - 独立: 基于 financial 光刻胶 +43% + 电镀液 +47% → 华为催化叠加后 60%
  - 引用: 上游定数录假设 60%，未独立修正（需说明接受理由）
```

**硬闸门（违反任一条 → 不得写入 step4 文件）**：

| # | 规则 | 检测方式 |
|:---:|------|------|
| 1 | 至少一个情景的 **营收 CAGR** 是独立计算的 | 必须出现从 financial 产品增速推导 CAGR 的计算过程 |
| 2 | 至少一个情景的 **目标 PS** 有独立来源 | 必须出现可比公司 PS 或案例折扣率计算 |
| 3 | 如果三个情景的涨跌幅与定数录偏差全部 < 5pct | ⛔ **视为未独立推演**，必须回退重算 |
| 4 | Bear 情景不是「Base 打个折」 | Bear 必须是独立证伪逻辑，有具体的触发事件 |

#### Step B — 与定数录对比

| 情景 | 你的涨幅 | 定数录涨幅 | 差异 | 差异原因 |
|------|---------|----------|------|---------|
| Bull | | | | |
| Base | | | | |
| Bear | | | | |

#### Step C — 差异分析（核心价值）

对每一个显著差异（>20pct），追查原因：

**差异可能来源**：
1. **数据基础不同**：定数录用的是错误/过时数据？（本川案例：96.5% GM 幻觉）
2. **PE 扩张假设不同**：你对 PE 的扩张/压缩幅度判断比定数录更保守/更激进？为什么？
3. **盈利增速假设不同**：你对新业务增速的判断不同？依据是什么？
4. **概率分配不同**：你认为 bull/bear 的概率应该更高/更低？基于什么催化剂判断？

**结论格式**：
```
定数录三情景：[合理 / 某情景需修正]
主要差异：bull 涨幅差异 XXpct，原因：定数录假设 PE 扩张至 XXx，我认为合理上限是 XXx（基于案例折扣率）
建议采用：[你的 / 定数录的 / 折中] 三情景
```

### 6. 不对称比 + 预期差

用你自己的三情景计算不对称比，与定数录对比：

```
你的不对称比: X.X | 定数录: Y.Y | 差异原因: ...
```

预期差用定数录的 BS 检测器输出（已在 Step 4 审计过输入），加上你自己的判断。

### 7. 估值综合结论

| 项目 | 结论 |
|------|------|
| 定数录模型路由 | 合理 / 需修正 / 错误 |
| 三情景 | 你 vs 定数录的主要差异及原因 |
| 建议采用 | 你的 / 定数录的 / 折中 |
| 不对称比 | 你 vs 定数录 |
| 估值安全边际 | 充足 / 一般 / 不足 |
