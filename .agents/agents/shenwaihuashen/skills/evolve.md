# 进化指令

## 触发条件

- 用户指出流程中的系统性错误
- 决策回撤 >15% 触发复盘
- 持仓退出后进行完整复盘
- 用户明确要求进化
- 发现可推广到所有标的的新规律

## 进化方法论

### 核心原则：抽象到根因，不堆叠补丁

> **每次进化只做一件事：从具体错误中提取通用原则，写入受影响的流程文档。** 不要列具体错误的 checklist——下次犯的会是新花样，checklist 全部失效。

**正确做法**：

```
具体案例 → 抽象根因 → 通用原则 → 写入流程

绿盟 3.2 亿搜索失败 + GM 72% 误判
    ↓
根因：第一轮搜索结果上就形成结论，没换维度再来一轮
    ↓
通用原则：穷尽搜索原则 — 负面断言的证据门槛远高于正面断言
    ↓
写入 data-verify.md §2
```

**错误做法（禁止）**：

```
绿盟 3.2 亿搜索失败
    ↓
规则："搜合同必须搜集团+省+招标三层"
    ↓                           ↑
绿盟 GM 72% 误判                这条规则在验证研发费用时完全没用
    ↓
规则："发现矛盾必须检查产品vs公司/含税vs不含税/订单vs收入"
    ↓                           ↑
下次遇到汇率换算差异             这些补丁都在解决同一个根因的不同表象
    ↓
规则："发现数据差异检查汇率换算"
...无穷无尽
```

### 进化执行流程

1. **识别根因**：问"这个错误如果再犯一次，会以什么新形式出现？"——如果答案不是当前表现，说明还没挖到根因
2. **抽象原则**：一句话说清。如果说不清，说明还没想透
3. **写入单一文档**：一条原则只写一个地方。多个文档重复同一原则 → 未来改一处忘一处
4. **删除旧补丁**：新原则覆盖了旧补丁的场景时，删除旧补丁，不留冗余
5. **一句话告知**：进化完成后，告知学到了什么、改了哪里
