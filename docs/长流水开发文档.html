一、系统定位

六条市场定律

  1. 每年都有站上风口的股票。取得重大突破、赚到大钱的公司，年年都会出现。
  2. 真正的交易机会都有过硬的逻辑。是大势，是能基于公开信息做出判断的，不是内幕、不是运气。
  3. 价格围绕价值上下波动。估值的锚始终存在，只是市场情绪会让它偏离。
  4. 上涨 10 倍的股票必先上涨 2 倍。十倍股不是一天涨出来的，中途有充足的确认和入场窗口。
  5. A 股的制度和市场环境总会给人入场参与十倍股的机会。跌停、回调、恐慌、质疑——都是门。
  6. 信息不是太少，是太多。核心瓶颈不是"找不到信息"，而是"被无关信息淹没"。

长流水的工作方式

基于以上定律，长流水的目标不是"预测股价"，而是做信息的过滤和聚焦：

阶段做什么核心手段
1. 过滤噪音 从海量产业资讯中排除无关事件、蹭概念标的、已充分定价的机会 LLM 分类 + 同源性判断 + 产业链定位
2. 识别范式 只关注能形成十倍股范式的机会——事件驱动、利润截留、估值有空间 LLM 总结 + V3 案例库模式匹配 + 产业链利润流分析
3. 估值推演 判断当前定价是否已经透支了故事的预期——还没充分定价的才值得深追 LLM 叙事→参数推导 + 代码估值计算 + LLM 审阅修正
4. 持续追踪 对筛选出的标的建立论点档案，持续跟踪论点变化、催化剂兑现、价格波动 追踪令系统 + 支柱评分卡 + 催化剂日历
5. 择时买卖 基于论点验证/证伪 + 价格偏离度，输出买卖信号 信号灯（买/持/减/卖）+ 风险触发器
核心洞察：LLM 的真正价值不在"推理深度"——而在分类和总结。海量信息中，99% 与十倍股无关。LLM 的任务是快速排除那 99%，让人的注意力集中在剩下的 1% 上。提示词编排调优是系统的核心，代码是辅助。

LLM 的角色

LLM 在长流水中不是"黑箱决策者"，而是分类器 + 总结器 + 搜索引擎编排器：

  • 分类：事件类型识别、锚类型判定、模型选择——把信息放进对的格子
  • 总结：从多源语料中提炼核心叙事、关键变量、脆弱点——让人能快速理解
  • 编排：决定搜索什么、何时搜索、何时停止——把搜索成本控制在合理范围
  • 所有算术由代码执行 — LLM 不直接计算市值/PE/涨幅。估值可靠性由代码保证

Python 端通过 config.json 中的 scheduler_enabled=true 启动周期性轮询：

{
  "scheduler_enabled": true,
  "tianji_poll_interval_sec": 1800,    # 天机卷轮询间隔 30分钟
  "polling_interval_sec": 3600         # 主轮询间隔 60分钟
}

调度器工作流程：

  1. fetch_unprocessed_records(limit=5) — 查询 mode=个股模式, level≥4, is_analyzed≠true, is_analyzing≠true 的记录
  2. lock_record(id) — 设置 is_analyzing="true" 防止并发
  3. 执行管线 (A→B→C)
  4. mark_tianji_processed(id) — 标记 is_analyzed="true"
事件写入：Coze 端的 Bot Studio (bstudio) 持续监控财经新闻/公司公告/券商研报并写入天机卷。mode 和 level 由 bstudio 在写入时设定。

4.1 LLM #1: 五维利润截留评估

维度评估内容评分示例
1. 议价能力对上游能否压价？对下游能否提价？high / medium / low
2. 集中度寡头还是散兵？CR3/CR5high / medium / low
3. 转换成本认证周期/产线绑定/监管壁垒high / medium / low
4. 增值比例该节点贡献最终产品价值的百分比具体数值
5. 需求弹性事件直接拉动该节点需求，还是间接蹭到？high / medium / low

隐性上游优先原则

产业链利润往往向"隐性上游"集中——体积小、价值密度高、认证壁垒极强的上游环节（芯片、特种材料、核心元器件），而非显眼的中游总装。

  • 若某上游环节占下游成品成本 <5% 但断供即瘫痪 → 利润截留极高
  • 中游总装即使产值大，若竞争分散、切换成本低，利润截留反而不如隐性上游
  • 不无限向上游追溯：只考虑一阶直接供应商

利润截留评分 (1-100)

分数含义
90-100绝对龙头节点（市占>50%+毛利率>30%+切换成本极高）
70-89强截留节点（寡头格局+高壁垒+高增值占比）
50-69中等截留节点
30-49弱截留节点
1-29几乎不截留

十六、关键设计决策

1. 信息过滤优先，而非分析优先

系统的第一性问题是"这个事件/标的值得看吗"。PreScreen 同源性判断、产业链无关排除、市值硬过滤——每层都在排除。LLM 的价值首先在于"把 99% 的无关信息排除掉"，而非对每个标的都深度分析。

2. 提示词编排是核心，代码是辅助

系统的核心能力在提示词。每一步 LLM 调用的 System Prompt 经过了反复调优——推理链顺序、思维禁区、打分锚定、证据纪律。代码负责数据抓取和算术计算，不替代 LLM 的判断。

3. 产业链先行，个股后行

产业事件不直接跳入个股分析。先理解产业链节点上的利润分配，再找节点内最具赔率的标的。这避免了"看到新闻→想到熟悉的大票→忽略产业链上游的真正赢家"的认知偏差。产业链分析已演进为三阶段架构——轻搜粗判→定向深搜→精析——以消除"粗判选谁谁赢"的自证预言。

4. LLM 不做算术

所有市值/PE/涨幅计算由代码执行。LLM 负责参数推导和逻辑审查。这消除了 LLM 算术错误（最常见失败模式）。Agent-3 的 LLM-1→代码→LLM-2 三明治结构是这个原则的工程体现。V8.2 新增了 LLM-2 前瞻信号硬约束——如果 LLM-1 遗漏重大信号，LLM-2 必须做出实质性参数修正（E309）。

5. Fail-open 默认放行

PreScreen 失败→放行。Tushare 不可达→跳过。LLM 不可用→Fallback。唯一硬终止是核心财务数据完全缺失（E101）。系统倾向"宁可看一个不那么完美的机会，也不错过一个真正的十倍股"。

6. V8 合并 Agent-2a+2b

V6/V7 中 Agent-2 拆分为 2a（叙事诊断）和 2b（模型路由），两个 LLM 独立判断同一件事。V8 合并为单次调用——消除序列化交接损耗和 route drift。V8.2 强化了事件优先法则：当多条叙事并存时，事件驱动的叙事是默认锚。

7. 持续追踪比单次估值更重要

估值报告是起点，不是终点。十倍股不是一天涨出来的（定律 4），中途有充足的确认窗口。追踪令系统的论点档案、支柱评分卡、催化剂日历——这些持续追踪机制才是真正捕捉十倍股的关键。

8. 搜索模组统一化（V8.2）

全管线搜索从 Bocha 迁移至火山引擎 Agent（结构化输出），三条管线（标准/SOTP/rNPV）共用统一搜索接口。火山引擎返回结构化报告而非碎片链接，信息密度更高。Bocha 作为辅助搜索工具保留在 Coze 工作流中。

9. change_log 审计验证 (V8.3)

_verify_change_log 自动剥离 scenario_valuation.scenario_details 前缀，修复了 B 模型 LLM-2 校正全部失效的系统性 bug——LLM-2 输出的 change_log path 带有完整路径前缀（如 scenario_valuation.scenario_details.base.target_ps），而校验函数期望裸字段名，导致所有 B 模型的 LLM-2 修正被静默丢弃。

10. ROIC 跨锚污染铁律 (V8.3)

LLM-2 提示词新增硬规则：收入锚模型（B/PS+TAM）禁止用"ROIC < WACC"作为下调 PS 的理由。ROIC 是利润锚指标，与 PS 锚定逻辑无关。用 ROIC 低来压 PS = 估值框架的跨锚污染。下调 PS 的唯一合法依据是：可比公司 PS 中枢、增长质量（增速/可见度/确定性）、盈利转化效率（毛利率→净利率的转化路径），以及事件揭示的具体风险（客户集中度/技术替代/产能天花板）。

11. SOTP Schema 防污染 (V8.3)

SOTP 提示词中的硬编码示例数据（如瑞华泰"化合物半导体 1.38 亿"）替换为占位符，防止 LLM 惰性复制示例数据导致跨标的估值污染。

12. 事件语料优先规则 (V8.3)

移除事件语料的 500 字符截断。新增"语料优先规则"：Agent-0 预研数据已在语料中的数字锚点（产能/价格/市占率）直接引用，不依赖最后一次搜索——因为搜索可能失败或返回过时信息，而已生成的预研语料经过了交叉验证。

十七、择时系统 (Agent-4) — 规划中

选股回答"该不该买"（论点对不对），择时回答"现在能不能买"（价格好不好）。两套正交的信号体系，不能混淆。

设计原则

核心洞察：择时因子必须与估值引擎的产出形成闭环。不是独立的技术分析层，而是对定数录结论的"市场面验证"。每个择时信号都应该能回答一个问题——"市场正在以什么速度、朝什么方向、带着多少确信度，朝我们的估值区间移动？"

三组择时因子

第一组：技术指标 — 趋势与结构确认

技术指标不单独做买卖决策，而是提供趋势方向、动量强度、波动率环境三个维度的客观描述。选用的都是大周期、少噪音的指标：

指标用途参数为什么用它而不是其他
MA60/MA120/MA250 中长期趋势方向 季度/半年/年线 十倍股全程在 MA60 上方运行。跌破 MA120 且论点 intact 是最佳入场区间。MA250 是最后的底线
ATR(20) 波动率 波动率环境判断 20 日 波动率收缩→扩张的转换点往往是主升浪起点。不需要判断方向，只需要判断"风暴前的平静"
成交量异常检测 资金参与度 20 日均量 ×2σ 十倍股起涨时普遍伴随放量。无量上涨是脆弱信号。放量下跌+论点 intact 可能是机会
价格结构（支撑/阻力） 入场/止损参考 关键价位 与定数录的 bear-base-bull 区间叠加。bear 估值 + 技术支撑 → 最强入场信号

不用 MACD/RSI/KDJ 的原因：它们假设价格围绕均值振荡。十倍股的价格行为是趋势+突破+范式切换——在上涨过程中会反复触发"超买"，用振荡指标择时会让你在 2 倍的时候就下车。

每日巡检

  • 价格日志追加：记录当日收盘价、PE、市值、累计收益率
  • 催化剂日历检查：今天是否有催化剂到期？有则标记 status，触发择时重评估
  • 财报/预告事件监听：天机卷有新事件关联到此标的 → 标记待处理
  • 价格偏离预警：当前价格突破 bear 下方 10% 或 bull 上方 → 推送

量化择时 + 因子

仓位管理

虚拟建仓

系统不接入实盘账户。虚拟建仓是一个模拟总仓，用于跟踪策略收益率。用户在实际券商账户中手动交易，追踪令的持仓数据与实盘保持一致。

虚拟建仓的核心机制：

  • 总仓位池：用户设定一个虚拟总资金（如 100 万），系统按比例分配
  • 信号驱动分配：择时判官产出 S/A/B/C/D 信号 + 建议仓位%，虚拟建仓按比例计算每只标的的持仓金额和股数
  • 用户手动同步：用户在实盘执行交易后，在追踪令中更新实际成交价和数量。系统据此追踪收益率
  • 收益率计算：基于追踪令 price_log 的每日收盘价，计算每只标的和总仓的累计收益率、最大回撤、夏普比率
  • 仓位再平衡提示：当某标的的择时信号变化导致建议仓位偏离当前仓位超过阈值，提示用户调整
为什么做虚拟建仓而不是接实盘：券商 API 接入的合规成本和维护负担太高。虚拟总仓 + 手动同步的方案，在保持追踪令持仓数据准确的前提下，用最低的工程成本实现了收益率跟踪。用户的交易决策仍然由追踪令的信号体系支撑——只是执行环节在系统外。

复盘

# 你是创新药管线估值分析师

核心能力是用事件驱动故事来驾驭估值参数，用参数反推故事的可信度。

## 估值哲学：故事+数字双螺旋
创新药管线估值的两个维度：
- **叙事层**: 管线组合解决什么临床需求？各阶段有哪些催化剂？事件推演中的传导链量化？
- **参数层**: PoS（成功率）、峰值销售、折现率、时间线。成熟业务的 PE/PS 倍数。
铁律：事件叙事决定参数的输入，参数反推叙事的可信度。

## 估值框架：两段式 SOTP
公司价值 = 成熟业务价值 + Σ 各管线药物 rNPV + 净现金

### 第一段：成熟业务估值
- 稳定盈利 → PE 估值（参照同类创新药企中枢，通常 25-55x）
- 微利/亏损 → PS 估值
- BEAR 中 PE 应回到行业周期底部（通常 15-30x）
- 成熟业务净利必须基于事件催化剂做前瞻估计，不能直接用 TTM

### 第二段：管线药物 rNPV
rNPV = PoS% × 峰值销售(亿) × 3 / (1 + 折现率%)^到峰值年数
- 专利倍数固定为 3x: 代表峰值后约 7 年的净现值近似。不可自行调整。
- 任务: 填 PoS、峰值销售、折现率、到峰值年数。代码用公式算。

**PoS 基准（按临床阶段）**:
Approved: 100% | NDA: 75-90% | Ph3: 50-65% | Ph2: 15-25% | Ph1: 8-12% | Preclinical: 3-8%

**调节规则**:
- 靶点已有同类药物获批 → +5-10ppt
- 靶点已有同类药物失败 → -5-10ppt
- 已有积极临床数据 → +5-10ppt
- 竞争格局激烈（≥3个同类在研）→ 峰值销售打折而非 PoS 打折
- 罕见病/突破性疗法认定 → +5-10ppt
