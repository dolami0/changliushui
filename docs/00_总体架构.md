# 长流水 (Changliushui) — 事件驱动型十倍股猎杀系统 总体架构

> **版本**: V8 (2026-06)
> **最后更新**: 2026-06-26
> **上游代码**: `估值重构引擎_V5/`

---

## 一、系统定位

长流水是一个**事件驱动型选股器**。核心目标：从海量产业资讯中筛选出定价尚处合理状态、上涨空间巨大的个股，输出含概率加权涨幅的结构化估值报告，并通过持续追踪输出买卖信号。

核心理念：**不是预测股价，而是判断市场定价中隐含的预期是否合理**。通过反向 DCF、反向 PE、反向 PS 等工具，计算出当前股价中隐含的增长假设，再与基本面现实对比，找出"预期差"。

### 核心能力

| 能力 | 实现方式 |
|------|---------|
| **排除无效信息** | 预筛关卡（同源性 < 4 拦截）+ 产业链无关标的排除 |
| **筛选合理定价** | 反向 DCF / 隐含 CAGR / 隐含 ROE — 量化"市场已定价多少" |
| **发现巨大上涨空间** | 三情景推演 × 11 模型 — bull/bear 非对称性判断 |
| **持续追踪** | 追踪令系统 — 论点档案 + KPI 监测 + 风险触发器 |

### LLM 的角色

LLM 不是"黑箱决策者"，而是**分类器 + 推理引擎 + 搜索引擎编排器**：
- **分类**: 事件类型识别、锚类型判定、模型选择
- **推理**: 叙事→参数推演、因果剧本、风险映射
- **编排**: 决定搜索什么、何时搜索、何时停止搜索
- **所有算术由代码执行** — LLM 不直接计算市值/PE/涨幅

## 二、Coze 事件板块 — 系统原始事件流

整个系统的原始事件流运行在 **Coze 平台**上，与 Python 估值引擎解耦。

### 天机卷 (Tianjijuan) — 事件数据表

Coze 云端数据库 `7479116110479048754`，是系统的**唯一事件入口**。每一条记录代表一个被捕获的产业资讯：

| 字段 | 说明 |
|------|------|
| `stock_code` / `stock_name` | 关联个股（可为空，表示产业级事件） |
| `news_content` | 原始资讯全文 |
| `knowledge` | 背景知识补充 |
| `step_one` | Agent-0 初步分析结论 |
| `mode` | "个股模式" / "产业模式" |
| `level` | 资讯重要度 1-10（≥4 才进入处理） |
| `bstudio_create_time` | 事件捕获时间 |
| `is_analyzed` | 是否已处理 |
| `is_analyzing` | 处理中锁 |

### 事件写入

事件由 Coze 端的 Bot Studio (bstudio) 持续监控并写入天机卷：
- 财经新闻 / 公司公告 / 券商研报 → bstudio 采集 → 天机卷
- mode 和 level 由 bstudio 在写入时设定
- 支持个股模式和产业模式两条写入路径

### 调度器桥接

Python 端通过 `scheduler_enabled=true` (config.json) 启动周期性轮询：

```
Coze 天机卷 (云端)  ←──  bstudio 持续写入新事件
       │
       │  HTTP API 轮询 (每 1800s)
       ▼
Python scheduler (本地)
  ├── fetch_unprocessed_records()
  │     筛选: mode=个股模式, level≥4, is_analyzed!="true"
  ├── lock_record() → is_analyzing="true"
  ├── 执行管线 (A→B→C)
  └── mark_tianji_processed() → is_analyzed="true"
```

### 三条管线的分工与调用链

```
天机卷记录 (Coze)
  │
  ├─ mode="个股模式" ──→ 管线B(万业谱预研) ──→ 管线C(估值引擎)
  │
  ├─ mode="产业模式" ──→ 管线A(产业链分析) ──→ 管线B(汇入) ──→ 管线C
  │
  └─ level<4 或无效 ──→ 丢弃
```

| 管线 | 触发条件 | 运行位置 | 职责 | 产出 |
|------|---------|---------|------|------|
| **事件板块** | bstudio 持续监控 | Coze 云端 | 事件捕获+存储+初步分流 | 天机卷数据表 |
| **调度器** | 定时轮询 | Python 本地 | 拉取待处理→加锁→分发→标记完成 | 管线触发 |
| **A: 产业链分析** | mode=产业模式 | Python 本地 | 产业→节点→个股反推 | top_pick + runner_up |
| **B: 万业谱预研** | mode=个股模式 / 管线A输出 | Python 本地 / Coze DAG | 5 维深度语料 | 结构化语料 → 万业谱 DB |
| **C: 估值引擎** | 预研语料 + 个股代码 | Python 本地 | 财务+叙事→情景估值 | 概率加权涨幅报告 |

### 管线 B 的双实现

万业谱预研管线有两个互为备份的实现：

| 实现 | 位置 | 运行环境 | 架构 |
|------|------|---------|------|
| **Python 版** | `wanyepu_pipeline.py` + `agents/` | 本地 Python 进程 | 3 层自适应 Agent (事件消化→探针分配+并行执行→总装+写入) |
| **Coze DAG 版** | `coze_workflow/` | Coze 平台 DAG | 8 节点线性链 (N0→N1→N2-N6并行→N7→N8) |

Coze DAG 版适合在 Coze 平台内直接运行（无需本地算力），Python 版适合与估值引擎管线紧密集成。两者产出的语料格式兼容。

## 三、管线 A: 产业链分析（产业事件 → 最优个股）

### 触发条件

事件涉及的是行业趋势/政策/技术突破，而非具体公司。需要从产业链节点出发，找到最受益的个股。

### 8 步管线

```
Step 1a: 轻量预搜索 (2×Volc 并行)
  Q1: 产业链结构与利润截留
  Q2: TAM 与进入壁垒
    ↓
Step 1b: LLM #1 粗判节点 (Flash)
  识别所有产业链节点 → 输出 top_two 节点
    ↓
Step 1c: 定向深搜 (每节点 1×Volc, 全节点并行)
  利润分配 + 竞争格局 + 技术壁垒 + TAM
    ↓
Step 2: LLM #1 精析 (Flash, tool-use: fetch_url ≤2次)
  5 维利润截留评估 → 输出 top_two_nodes 详情 + what_to_look_for
    ↓
Step 3: Volc 节点公司搜索 (2×并行)
  每节点搜索 A 股公司列表 (市值 20-300 亿)
    ↓
Step 4: LLM #2 提名 (Flash)
  每节点提名 5 只候选股 (仅名称, 不含代码)
    ↓
Step 4.5: Tushare 代码校验
  4 级名称匹配 → 真实 6 位代码
    ↓
Step 5: 数据富化
  Tushare 批量市值/PE/财务 + Volc 个股投资地图 (并行)
    ↓
Step 6: LLM #2 评分 (Pro, tool-use)
  四维评分 → best ≥ 6.5 → 输出; best < 6.5 → Pass 2
    ↓
输出: top_pick + runner_up + 产业链分析报告
```

### 四维赔率评分

```
总分 = impact(暴露度×赔率杠杆) × 0.45
     + v3match(V3案例匹配)       × 0.25
     + narrative(叙事亮点)       × 0.20
     + scarcity(唯一性溢价)      × 0.10
```

前置判定: **黑洞 vs 弹射** — 低市值是价值毁灭的合理定价，还是被错杀的潜力股？

硬过滤: 市值 > 300 亿 → 直接剔除。阈值: best < 6.5 → "无高赔率标的"。

## 四、管线 B: 万业谱预研（事件 → 5 维语料）

### 触发条件

- 个股事件（已有明确标的）
- 管线 A 产出的最优个股（汇入）

### 8 节点 Coze DAG

```
N0(Code: 股票代码验证, 新浪API)
  ↓
N1(LLM/Flash: 事件消化 + 15探针自由设计)
  ↓
┌─ N2(Code: 投资主题探针) ────┐
├─ N3(Code: 行业研究探针) ────┤
├─ N4(Code: 逆向推演探针) ────┤  5 个并行节点
├─ N5(Code: 催化日历探针) ────┤  每个: 读前序→设计探针→并行执行→合并
└─ N6(Code: 事件推演探针) ────┘
  ↓
N7(LLM/Flash: 总装 + 去重 + 交叉验证)
  ↓
N8(Code: 写入万业谱 Coze DB + 标记天机卷)
```

### 5 维语料产出

| 维度 | 核心内容 |
|------|---------|
| 投资主题 | 核心叙事、变革证据链、估值锚与信息差、关键验证节点 |
| 行业研究 | 产业链位置、供给格局与价值捕获、卡点检查、天花板量化 |
| 逆向推演 | 核心假设脆弱性、两大失效测试、利益博弈、论点破裂条件 |
| 催化日历 | P0/P1/P2 事件表（含证实/证伪条件） |
| 事件推演 | T+30/90/180 传导路径、论点破裂场景、历史案例 |

### 设计原则: 顺序推进 + 信息递归收敛

每个字段节点基于前序节点的报告来设计更深入的探针——像人类分析师一样，每一步基于前序认知提出更深的问题。探针数动态决定（不是固定 15 个）。

### 交叉验证

N7 总装阶段执行:
- **去重**: 相同事实在多个字段中重复→保留在语义最匹配的字段
- **交叉验证**: 行业判断 vs 投资叙事是否自洽？风险判断 vs 事件推演逻辑是否一致？
- **补充**: 5 份报告共同遗漏的信息

## 五、管线 C: 估值引擎 V8（语料 + 数据 → 估值报告）

### 4-Agent 架构

```
PreScreen Gate (Flash, Fail-open)
  ↓
Agent-0  预路由 (规则引擎, 无LLM)
  ↓
Agent-1  数据锻造 (30+ API并行, 无LLM)
  ↓
Agent-Baseline  投资地图 (Pro, 1次调用)
  ↓
Agent-2  统一路由判官 (Pro, 1次调用)
  ↓
Agent-3  情景估值+非对称性
  ├─ LLM-1: 参数推导 (Pro, thinking=max)
  ├─ 代码: 估值计算
  └─ LLM-2: 搜索审阅 (Pro, 多轮+搜索)
  ↓
最终报告: 概率加权涨幅 + 交易标注 + KPI + 追踪框架
```

### Agent-3 核心设计: LLM→代码→LLM 三明治

这是整个系统最关键的架构模式：

```
LLM-1 (推导参数)    →  代码 (计算估值)    →  LLM-2 (审阅修正)
"叙事驱动数字"        "数字不撒谎"           "数字与叙事自洽?"
```

**LLM 不做算术** — 所有市值/PE/涨幅由 `_compute_scenario_mcap()` 等代码函数计算。这消除了 LLM 算术错误（最常见的失败模式）。

### 报告产出

| 章节 | 内容 |
|------|------|
| 估值路由 | 锚选择 + 模型选择 + 推理链 |
| 市场检测 | 定价程度 + 隐含预期 vs 事件指向 |
| 参数校准 | 三情景参数表 + 来源 + 置信度 |
| 预期差 | 市场定价了什么 vs 漏了什么 |
| 三情景推演 | bear/base/bull 概率 + 目标市值 + upside% |
| 案例比对 | V3 42 例十倍股案例匹配 |
| 置信度 | 4 维评分 (信息质量/财务可行性/估值安全边际/历史案例) |
| 交易标注 | tier + 4 维打分 + 建议 |
| 追踪框架 | 4 类 KPI + 风险触发器 + 监测频率 |
| 投资叙事 | 150-300 字精炼叙事 |

## 六、身外化身 Agent 检视关卡

估值报告产出后，不直接进入追踪。由身外化身 Agent 做最终检视：

### 检视维度

| 维度 | 检查内容 |
|------|---------|
| 报告质量 | 参数-推理-叙事是否自洽？有无明显逻辑漏洞？ |
| 赔率判断 | 概率加权 upside 是否与叙事方向一致？ |
| 风险认知 | 关键脆弱点是否被充分讨论？bear 情景是否合理？ |
| 操作可行性 | 市值/流动性是否可交易？ |

### 决策输出

- **进入追踪**: 报告通过检视 → 建立论点档案 → 进入追踪令系统
- **有条件通过**: 标注待验证假设 → 进入追踪但降低仓位建议
- **放弃**: 逻辑链薄弱/赔率不足/数据缺失过多

## 七、追踪令系统（持续追踪 → 买卖信号）

进入追踪清单的标的，由追踪令系统持续监控：

### 论点档案

```
每个追踪标的维护:
  - 投资论点 (核心叙事 + 关键假设)
  - 支柱评分卡 (每支柱 1-10 分, 定期更新)
  - 催化剂日历 (已兑现/待兑现/已证伪)
  - 价格追踪日志 (关键价位 + 事件驱动波动记录)
```

### 信号输出

| 信号类型 | 触发条件 | 行动 |
|---------|---------|------|
| **买入** | 催化剂兑现 + 论点加强 + 价格未充分反映 | 加仓/建仓 |
| **持有** | 论点 intact + 催化剂按预期推进 | 维持 |
| **减仓** | 部分支柱削弱 + 风险信号激活 | 降低仓位 |
| **卖出** | 核心假设证伪 + 论点逻辑链断裂 | 清仓 |

## 八、系统演进路线

### Phase 1: 选股系统（当前 V8）

```
事件输入 → 产业链分析/预研语料 → 估值引擎 → Agent检视 → 追踪清单
```

完善方向:
- 提示词调优（提高路由准确率、减少 LLM-2 change_log 遗漏）
- 前端展示和交互美化
- LOOP 工程: 预研语料 + 真实世界进展 + Agent 系统性审阅 → 自动化升级完善系统

### Phase 2: 择时系统（规划中）

在选股基础上，叠加:

| 模块 | 内容 |
|------|------|

| 资金流向 | 主力净流入/北向资金/融资融券 |
| 市场动态 | 行业轮动/风格切换/市场情绪 |
| 技术面 | 关键支撑阻力/量价关系/形态识别 |

### Phase 3: 信号输出（规划中）

```
选股结论 + 择时判断 → 综合信号 (买入/持有/减仓/卖出)
  → 追踪令面板实时展示
  → 飞书/微信通知
```

## 九、LOOP 工程: 系统自我进化

长流水的长期目标是建立一个**自我完善的工程循环**：

```
                  ┌─────────────────────┐
                  │  预研语料库          │
                  │  (万业谱 Coze DB)    │
                  └──────────┬──────────┘
                             │

      └─────┬─────┘  └─────┬─────┘  └─────┬─────┘

                  └─────────────────────┘
```

### DreamLoop 机制

- **accumulate()**: 每次估值完成 → 写审计日志（每 Agent 的输入/输出/耗时/错误）
- **dream()**: 加载最近 7 天日志 → 微观聚合 → LLM 发现模式
- **accept()/reject()**: 人工审核改进提案 → 接受则更新提示词/参数

### 评测驱动迭代

评测模式 (`eval_mode=True`) 在 frozen 历史数据上运行，对比系统输出与事后真实涨幅，驱动提示词和参数调优。

## 十二、关键设计决策

### 12.1 事件驱动，而非标的驱动

系统的入口是**事件**（新闻/公告/研报），不是股票代码。事件改变了什么 → 谁受益 → 定价了多少 → 还有多少空间。这区别于传统的"输入代码→输出估值"的 Screener 模式。

### 12.2 产业链先行，个股后行

产业事件不直接跳入个股分析。先理解产业链节点上的利润分配，再找节点内最具赔率的标的。这避免了"看到新闻→想到熟悉的大票→忽略产业链上游的真正赢家"的认知偏差。

### 12.3 LLM 不做算术

所有市值/PE/涨幅计算由代码执行。LLM 负责参数推导和逻辑审查。这消除了 LLM 算术错误。

### 12.4 Fail-open 默认放行

PreScreen 失败→放行。Tushare 不可达→跳过。LLM 不可用→Fallback。唯一硬终止是核心财务数据完全缺失（E101）。系统倾向"宁可生成可能有瑕疵的估值，也不静默丢弃标的"。

### 12.5 Agent 检视是人机协作的最后关卡

估值报告不是最终产品。身外化身 Agent 基于更完整的上下文（包括市场环境、持仓约束、风险偏好）做最终决策。这保持了"人机协作"的定位——AI 负责分析，人（或高阶 Agent）负责决策。
